- (direction) User: backoffice section "Contenuti pagine" in the sidebar, with one sub-section per page; today only the home, so one entry "Home"
- (direction) User: from the Home page admin edits title, hero image, CTA, subtitle and statistics
- (direction) User: content must reach the front-end as JSON taken from an API
- (question) User: an API call adds latency, the page would be empty meanwhile and SEO suffers; is there a better way?
- (decision) Latency/SEO problem exists only for a browser-side fetch. Landing is Next.js: fetch on the server, keep the page static, regenerate on demand after a save. User confirmed Next.js and asked for a spec prompt for the landing task
- (decision) Options weighed: on-demand regeneration (chosen), time-based regeneration (simpler, delay), full rebuild per save (slow), client fetch (rejected)
- (decision) Trigger is a Supabase Database Webhook to a secret-protected landing endpoint: the backoffice SPA cannot hold a secret
- (decision) Page images in a public bucket `page-images`: signed URLs of `question-images` expire after 1h and cannot live in a cached page. Dedicated uploader, not the question image library
- (decision) One table `page_contents` (id, slug, content jsonb); one JSON document per page; RPC `get_page_content(slug)` is the API; anon has no table access
- (decision) Rows seeded by migration, admin can only update: a page must exist in landing code first
- (decision) Database validates only "content is an object"; form validates with zod; landing treats JSON as untrusted and falls back to current hard-coded copy
- (assumption) CTA = button text + note under it; target `/quiz` not editable
- (assumption) Alt text required with a custom hero image (not asked by user; accessibility and SEO)
- (assumption) Max 4 statistics to fit the layout; saving publishes immediately, no drafts
- (question) Landing hosting platform not confirmed: on-demand regeneration needs a server runtime
